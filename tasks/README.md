Темы ЛР2–5 приведены по программе предыдущего семестра. Требования к их реализации будут опубликованы в новых редакциях заданий.

## Выполнение работы

Перед началом работы завершите [регистрацию](../PR-RULES.md#регистрация).

1. Прочитайте задание и контракт адаптера, если он предусмотрен.
2. Подготовьте данные по требованиям работы.
3. Реализуйте алгоритм и библиотечный эталон.
4. Проведите эксперименты.
5. Запишите результаты и выводы в `README.md` лабораторной.
6. Отправьте работу по [инструкции подготовки PR](../PR-RULES.md).

## Исходники и зависимости

Пишите реализацию на Python в `.py`-файлах. Поиск разбиений, обучение и другие операции, которые задание требует реализовать самостоятельно, выполняются вашим кодом. Для библиотечного эталона используйте указанную в задании реализацию. Разрешённые исключения, например использование библиотечного базового алгоритма в ансамбле, определяются заданием конкретной работы.

Внутреннюю архитектуру и оптимизации выбирайте самостоятельно. Если для работы предусмотрен адаптер, реализуйте опубликованный контракт. Для ЛР1 это [API v1](task-01/api.md).

Зависимости зафиксируйте в `requirements.txt` своей лабораторной. В отчёте укажите версию Python и команды подготовки окружения, получения данных и воспроизведения эксперимента. Зависимости адаптера автоматически устанавливаются из `requirements.txt` лабораторной. Подробности подготовки окружения ЛР1 описаны в контракте API.

## Данные и воспроизводимость

Укажите источник датасета и подготовьте скрипт получения данных из внешнего источника. Опишите необходимые авторизацию, согласие на использование или ручной шаг скачивания, если они требуются источником. Локальные данные храните вне отслеживаемых файлов Git.

Подготовку обучающей, валидационной и тестовой выборок выполняйте по заданию. Фиксируйте начальное состояние генератора случайных чисел. Преобразования, которым требуется обучение, настраивайте на обучающей выборке. Для подбора параметров используйте предусмотренную заданием валидацию, включая OOB или кросс-валидацию, когда они указаны в работе. Тестовую выборку используйте для итоговой оценки.

Датасеты, кэши, окружения и файлы данных с результатами экспериментов запрещены в коммитах PR. Численные результаты приводите таблицами в отчёте, графики сохраняйте рядом с ним. Полный список форматов и правила проверки истории приведены в [правилах подготовки PR](../PR-RULES.md#допустимые-файлы).

## Отчёт

В `README.md` каждой лабораторной включите следующие сведения.

1. Цель работы и краткое описание реализованного алгоритма.
2. Источник данных, признаки, целевую переменную и подготовку выборок.
3. Версии зависимостей и команды воспроизведения эксперимента.
4. Параметры собственной модели и библиотечного эталона.
5. Таблицы метрик и сравнение результатов.
6. Графики с подписями осей и легендой, когда она нужна.
7. Выводы, объясняющие полученные результаты.

Конкретные метрики и эксперименты задаёт лабораторная. В ЛР1 требуется сравнение собственного дерева до и после редукции с библиотечным деревом.

## Проверка и сдача

«Оформление PR» проверяет тип PR, отслеживаемые файлы, историю коммитов и комплектность работы. «ЛР1 / closed» проверяет реализацию через адаптер на закрытых преподавательских примерах. Интерпретация статусов и действия при ошибках описаны в [инструкции подготовки PR](../PR-RULES.md#результаты-автопроверок).

Преподаватель проверяет код, эксперимент и отчёт. На устной сдаче студент объясняет алгоритм, реализацию, параметры и результаты экспериментов.
