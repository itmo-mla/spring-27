# Подготовка лабораторных и PR

## Регистрация

1. Создайте fork `itmo-mla/spring-27` в своём аккаунте GitHub.
2. Создайте в нём `students/ivanov-ii/README.md`, заменив имя каталога на свою фамилию и инициалы латиницей.
3. Укажите в файле свои ФИО и группу.
4. Откройте отдельный PR в `itmo-mla/spring-27`, ветка `main`.
5. Дождитесь принятия регистрации.

Пример названия PR — `Регистрация. Иванов И. И.`. В регистрационный PR входит только файл регистрации. [Структура каталога студента](students/README.md)

## Ветка для лабораторной

Склонируйте свой fork и добавьте основной репозиторий как `upstream`. Вместо `YOUR_LOGIN` укажите свой логин.

```sh
git clone https://github.com/YOUR_LOGIN/spring-27.git
cd spring-27
git remote add upstream https://github.com/itmo-mla/spring-27.git
```

После принятия регистрации получите актуальную базовую ветку.

```sh
git fetch upstream
```

Создайте ветку для ЛР1 от этой версии курса.

```sh
git switch -c lab1 upstream/main
```

Для следующей работы снова выполните `git fetch upstream` и создайте новую ветку от `upstream/main`, например `lab2`. Это позволяет сформировать отдельную историю изменений каждой лабораторной.

## Открытие и обновление PR

1. Подготовьте работу по [заданию](tasks/README.md).
2. Проверьте состав изменений и коммитов своей ветки.
3. Отправьте ветку в свой fork.
4. Откройте PR в `itmo-mla/spring-27`, ветка `main`.
5. Дождитесь автопроверок на последнем коммите.
6. Исправьте замечания в той же ветке.
7. Пройдите устную сдачу.

Пример названия PR — `ЛР1. Иванов И. И.`. В описании укажите номер лабораторной, каталог работы, команду запуска эксперимента и особенности получения данных. Если вы исправляете замечания, кратко перечислите исправления.

## Состав и история изменений

**Один PR содержит одну лабораторную одного студента.** В PR лабораторной меняется только её каталог, например `students/ivanov-ii/lab1/`.

Проверяются итоговый diff и каждый коммит ветки, отсутствующий в базовой ветке курса. Изменение предыдущей лабораторной с последующим восстановлением остаётся нарушением истории PR.

Если запрещённый файл добавлен одним коммитом и удалён следующим, очистите историю ветки. Это правило распространяется на кэши, окружения, датасеты и файлы данных с результатами. Добавление шаблона в `.gitignore` предотвращает новые добавления, но уже записанные коммиты нужно исправить отдельно. Собственные исключения добавляйте в `.gitignore` внутри каталога лабораторной.

Удаление запрещённого файла, который уже находился в базовой ветке до PR, разрешено. При слиянии базовой ветки унаследованные изменения отделяются от новых изменений студента. Неотслеживаемые локальные файлы в проверку PR не входят.

## Допустимые файлы

| Сохраняйте в Git | Храните локально вне отслеживаемых файлов |
|---|---|
| Исходники `.py` в `source/` или `sources/` | Датасеты и архивы данных |
| Отчёт `README.md` с таблицами метрик | CSV и другие файлы данных с результатами экспериментов |
| Необходимые графики, включая PNG и PDF | Кэши и временные файлы |
| `adapter.py` и зависимости лабораторной | Виртуальные окружения и установленные пакеты |
| Конфигурация и документация | Локальный `.env` |

Датасет должен получаться из внешнего источника способом, описанным в отчёте. Для ЛР1 также запрещены `.ipynb`.

## Результаты автопроверок

| Проверка | Что проверяет |
|---|---|
| «Оформление PR» | Отслеживаемые файлы и историю коммитов, включая изменения вне текущей лабораторной |
| «ЛР1 / closed» | Вычислительную часть ЛР1 через адаптер на закрытых преподавательских примерах |

Каждый результат относится к полному SHA, указанному в проверке. После нового push ориентируйтесь на результаты нового коммита.

| Условие | Действие студента |
|---|---|
| «Оформление PR» сообщает нарушение | Откройте указанный коммит и исправьте состав или историю своей ветки |
| «ЛР1 / closed» сообщает неверный результат, нарушение API или ошибку выполнения | Исправьте реализацию или адаптер по указанному требованию |
| Сработал ресурсный лимит | Проверьте завершение вызова, использование памяти и условия окружения из API |
| Сообщён сбой инфраструктуры | Сообщите преподавателю номер PR и проверенный SHA |
| Запуск отменён или PR обновился | Дождитесь проверки актуального коммита, при необходимости обратитесь к преподавателю |
| Обе проверки успешны | Подготовьтесь объяснить реализацию, эксперимент и выводы на устной сдаче |

Преподаватель может повторно запустить проверки через Actions. Решение о приёмке работы принимает преподаватель после проверки кода, отчёта и устной сдачи.

## Исправление истории

Перед переписыванием истории убедитесь, что работаете в своей ветке лабораторной, и сохраните нужные изменения.

Уберите запрещённые файлы или посторонние изменения из соответствующих коммитов, например через интерактивный rebase. Затем проверьте итоговый diff и историю относительно актуальной `upstream/main`.

```sh
git log --oneline upstream/main..HEAD
git diff --stat upstream/main...HEAD
```

После изменения истории отправьте свою ветку с защитой от перезаписи чужих обновлений.

```sh
git push --force-with-lease origin lab1
```

Замените `lab1` на имя своей ветки. PR обновится автоматически, и проверки запустятся для нового SHA.
